## Мини-CMS на файлах

У каждого поста — `.md`-файл с YAML-подобной шапкой:

```text
---
title: Заголовок
date: 2026-11-17
tags: zig, seo
description: Мета-описание
slug: custom-slug
draft: false
---
# Тело статьи markdown…
```

## Парсер без YAML-зависимости

`content.zig` реализует подмножество: файл обязан открываться и закрываться строкой `---`, внутри — только `key: value`. Неизвестные ключи игнорируются, кривой frontmatter деградирует в «нет frontmatter» — опечатка не уронит блог.

Поддерживаемые ключи: `title`, `date`, `author`, `tags`, `description`, `slug`, `draft`.

## Нормализация slug и тегов

- `slug` не задан → берётся имя файла; задан → используется как есть, но **всё прогоняется через `markdown.slugify`**.
- `tags` — список через запятую; каждый тег тоже slugify'ится и дедуплицируется.
- Slug всегда `[a-z0-9-]`: латиница в нижнем регистре, кириллица транслитерируется, остальное отбрасывается. Это делает параметры `[slug]`/`[tag]` безопасными для сырого среза пути.

## Сортировка и черновики

Посты сортируются по `date` по убыванию; посты без даты — в конец. `draft: true` (также `yes`/`1`) исключает файл из загрузки целиком — черновик не виден ни в HTML, ни в RSS, ни в sitemap.

## Границы подхода

Файловая CMS не масштабируется до тысяч постов без кэша, не имеет ревизий и не дружит с нетехническими авторами. Для блога на десятки статей — идеально: git-история вместо CMS, деплой = копирование файлов.
