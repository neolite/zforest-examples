## Зачем ещё один блог

В экосистеме zforest уже есть доска, монитор и букинг — но не было места, где можно длинно писать о самой платформе. ZBlog закрывает этот пробел: **полностью read-only** приложение, которое рендерит markdown-файлы в HTML на сервере.

Ключевое решение — контент живёт в `content/posts/*.md`, а не в SQLite. Блог не пишет ничего: ни комментариев, ни черновиков в базе. Это убирает целый класс проблем — миграции, блокировки, бэкапы базы.

## Архитектура в двух словах

- **Роутинг** генерируется `zig build gen` из файлов в `pages/`: `post/[slug].zig` → `/post/<slug>`, `rss.xml.zig` → `/rss.xml`.
- **Контент** сканируется один раз при старте: frontmatter-парсер + markdown-рендерер из `plugins/`.
- **View** — обычные `forest.Node`-деревья; layout добавляет `<header>`/`<main>`/`<footer>`.

## Что даёт zmeta

Zmeta берёт на себя шаблонный бойлерплейт: сессии, `<head>`-спеки на страницу, raw-эндпоинты и диспетчер действий. Блог объявляет `head()` у каждой страницы — и получает canonical, Open Graph и JSON-LD без единой строчки middleware.

> Правило простое: страница знает свой SEO-контекст лучше всех — значит, и `<head>` должен собираться на странице.

## Производительность

Весь CSS — один inline-блок в `<head>` (~6 КБ), весь контент — SSR без клиентского JS. Страница поста весит меньше 30 КБ вместе с разметкой.

| Слой | Технология |
|------|-----------|
| Роутинг | file-based codegen |
| Контент | markdown + frontmatter |
| View | forest.Node SSR |
| SEO | HeadSpec + plugins/seo |

## Что дальше

В планах — пагинация архива (уже есть), поиск по excerpt и тегам (тоже есть), а дальше, возможно, черновики через `draft: true` и предпросмотр.
