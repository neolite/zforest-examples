## Зачем свой парсер

Zig-мир не богат markdown-библиотеками, а требования к безопасному выводу у нас жёсткие: **никакого raw HTML passthrough**, весь текст экранируется, whitelist тегов. Проще написать свой консервативный рендерер, чем аудитить чужой.

Парсер живёт в `plugins/markdown.zig` — переиспользуемом compile-time модуле, который blog делит с другими приложениями репозитория.

## Что умеет

- ATX-заголовки `#`–`######` со **стабильными slug-id**: `## Hello World` → `<h2 id="hello-world">`. Кириллица транслитерируется — «Привет, мир» → `privet-mir`.
- Fenced code с языком: ` ```zig ` → `<pre><code class="language-zig">` (подсветки нет — v1).
- Списки: маркированные, нумерованные, **вложенные**.
- Инлайн: `code`, **bold**, *italic*, ~~strike~~, [ссылки](url), ![картинки](src).
- Цитаты `>`, горизонтальные линии `---`, GFM-таблицы.

## Как это безопасно

Рендерер возвращает `forest.Node`-дерево, где весь пользовательский текст проходит через экранирование. Сырой HTML из markdown просто **не поддерживается** — тег `<script>` в статье отрендерится как текст.

```zig
const nodes = markdown.renderBlocks(a, post.body);
// nodes — готовое дерево для forest.writeHtml
```

## Slug-алгоритм

Заголовок нормализуется: lowercase, пунктуация → дефисы, кириллица → транслитерация, повторные дефисы схлопываются. Один и тот же заголовок всегда даёт один id — на этом держатся якорные ссылки и оглавление статьи.

## Ограничения v1

Нет синтаксической подсветки кода, нет footnotes, нет definition lists. Всё это можно добавить позже — архитектура (блочный → инлайн конвейер) к этому готова.
